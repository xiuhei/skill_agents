# UI Design

## 0. 约束

本 Skill 适用于从零生成 UI、修改已有 UI、依据设计稿实现、审核截图或代码。默认产出**简洁、专业、可信、内容有用**的产品界面。用户已明确指定的品牌设计和既有产品规范优先；任何偏离须有实际业务依据。

**交付前四项硬门禁：**

1. **图标门禁：** AI 自行设计的界面中，禁止使用 Emoji、彩色表情字符或 Emoji 字体充当按钮、菜单、导航、功能卡片、提示等 UI 图标。使用项目已有 SVG/Icon 组件；缺失时引入一套成熟的同风格图标。用户实际输入的表情、聊天消息、昵称以及明确要求显示的内容应保留。
2. **色彩门禁：** 默认只使用黑、白、灰的中性色阶（通常用近黑、灰白，避免大面积极端纯黑纯白）。不得随意加入紫色、蓝紫渐变、荧光色、彩色卡片、彩虹背景、彩色图标或“科技感”装饰。品牌色只有在用户指定或项目现有规范要求时使用；错误/成功/警告等语义色可少量使用，不能把语义色当装饰色。
3. **文案门禁：** 每一段**可见文字**都必须承担明确的产品功能：识别位置、说明数据、帮助操作、反馈状态或提供必要的业务内容。禁止向界面塞入设计说明、实现思路、需求复述、提示词、装饰性副标题、无意义标签、虚构统计、占位营销话术与调试信息。
4. **布局门禁：** 页面以桌面 `12×12`、平板 `9×9`、手机 `4×12` 三套网格作为布局基准,部分网格可做调整,但一般为4,6,8,9,12。列控制水平排版，行只作首屏/工作区的逻辑分区；滚动内容自然增长。

## 1. 工作方式：先继承，再设计，最后审查

1. **检查项目。** 识别技术栈、现有页面、真实业务数据、导航结构、已有 Token、图标库、组件库、字体、主题、交互约定。优先沿用项目稳定规范。
2. **复用成熟实现。** 优先现有组件；必要时选用对应平台的成熟组件/图标方案，如 Radix、shadcn/ui、Ant Design、Fluent、Material、Apple 平台组件等。不要重复实现可访问菜单、焦点陷阱、对话框和选择器。
3. **把需求与文案分开。** 将用户指令拆为 `功能需求`、`视觉规则`、`交互约束`、`明确要求展示的文字`、`真实业务数据`。前三类仅指导实现，不能直接渲染到页面。用户没有要求展示的解释性文字一律不补。
4. **先定内容清单。** 明确当前页面真正需要的导航名、字段名、按钮、状态、必要业务文本；列出主操作与异常/空状态。识别可删除的解释性段落与空卡片。
5. **选定视觉与网格。** 默认中性黑白灰；按工作区宽度使用三套网格；定最小化 Token 与统一图标家族；再写组件。
6. **实现完整交互。** 对应业务状态、键盘/触控操作、错误恢复、缩放、滚动、响应式、暗色模式（如启用）。
7. **交付前审查。** 检查实际渲染的界面和可见文案，优先修复 Emoji、异常色彩、提示词泄露、多余文本及布局错位。能运行时真实启动、截图或走查；如实报告验证结果。

> 设计推理、网格说明、选色理由、组件建议只能写在 AI 回复、设计说明文档或开发注释中；默认不可出现在产品页面。

## 2. 视觉硬规范：干净的黑白灰界面

### 2.1 默认调色板

只有在项目没有既有主题且用户没有指定品牌色时，才用以下示例起步。使用语义 Token，避免在组件内散落原始色值。

| 语义 | 亮色默认 | 暗色默认 |
| --- | --- | --- |
| `canvas` 页面底色 | `#F7F8FA` | `#15171A` |
| `surface` 面板 | `#FFFFFF` | `#1E2125` |
| `surface-muted` 次级区域 | `#F0F2F4` | `#262A2F` |
| `text` 主要文字 | `#1B1D21` | `#ECEEF1` |
| `text-secondary` 次要文字 | `#555B63` | `#B5BBC3` |
| `border` 必要分隔 | `#DFE2E6` | `#363C43` |
| `primary` 主要操作 | `#26292E` | `#E9EBEE` |
| `on-primary` 主操作文字 | `#F8F9FA` | `#1B1D21` |

- 默认不用大面积纯黑 `#000000`、纯白 `#FFFFFF` 作为唯一背景，纯白局部卡面可以合理使用。颜色数量以功能需要为准，不为了填满“调色板”而添加颜色。
- 主按钮通过中性明暗反差强调；次级按钮采用文字或低对比表面。无需为每一张卡片、导航项分配一套颜色。
- 图表默认采用不同灰阶、线型、纹理和直接标签；区分度不足时才采用克制、可访问的辅助色，且同屏数量受控，不能只靠颜色传达数据。
- 状态色只用于真实含义：失败/危险、成功、警告、待处理；优先让文字和图标共同表达状态，不将整张卡片染成高饱和背景。
- 禁止默认生成蓝紫渐变、彩色玻璃拟态、霓虹描边、大面积 Glow、渐变标题、无意义彩色光斑。用户明确要求或产品品牌需要时才例外。
- 背景色阶、留白和细分隔线都可表达层次；禁止卡片套卡片的无意义边框堆叠。交互焦点与必要的表格边界必须保留。

### 2.2 图标统一规则

- **优先顺序：** 项目已有图标库 → 项目既有平台原生图标 → 单一成熟图标库。Web 默认可选 Lucide / Heroicons；选择一种后保持全局一致。原生客户端用对应原生组件或授权的 SVG 资源。
- 图标必须语义准确。用 `search` 表示搜索、`settings` 表示设置、`folder` 表示目录；没有合理匹配时允许纯文本按钮，禁止以 Emoji 顶替。
- 同一层级统一光学尺寸、线宽、圆角语言和对齐。常见图标大小为 `16 / 18 / 20 / 24` 平台单位；优先复用库的默认线宽，避免一个页面混合填充、描边、写实彩色和 3D 图标。
- 默认图标颜色继承文字色；状态图标才用对应语义色。Logo/品牌图标使用真实授权资产，不用相似 Emoji 冒充。
- 图标按钮要有可访问名称（Web 使用 `aria-label` 等）；纯装饰图标应从读屏顺序隐藏；只有图标会造成操作歧义时提供简短可见标签。
- AI 生成的静态标题、数据示例、空状态和按钮，不得出现 `🚀`、`✨`、`🔥`、`🎯`、`📁` 等作为插画或图标的 Emoji。允许用户原始数据包含表情，不篡改数据。
- 禁止使用 Unicode 私用区、图标字体乱码、系统 Emoji 回退当“图标方案”。资源缺失时选择文本优先、补齐成熟图标依赖。

### 2.3 避免 AI 模板味

- 不自动创建“顶部小胶囊标签 + 夸张标题 + 解释性副标题 + 三个功能卡片”的固定样板。
- 不用无意义的 `01 / 02 / 03`、`PRO`、`NEW`、`BETA`、`智能`、`高效` 作为点缀；只有真实编号、产品状态、付费等级才显示。
- 避免每个区域都加标题、描述、分隔线、阴影和卡片；局部密度由内容决定。一个视觉焦点通常足够。
- 避免每个按钮有阴影、每段文字渐显、每张卡片 hover 上浮、每块背景有光晕。交互反馈要克制且一致。
- 使用系统或项目已有字体优先；避免混搭无业务理由的标题字体。提升质感主要靠排版、间距、对齐与视觉层次。

## 3. 可见文字的“零噪声”规范

### 3.1 严格区分三类信息

| 信息类别 | 示例 | 能否进入 UI |
| --- | --- | --- |
| 用户的**设计/开发指令** | “按 12×12 网格排版”“使用黑白极简风格”“实现文件同步” | **不能直接显示**；仅作为实现要求 |
| 用户**明确指定的界面内容** | “页面标题显示‘我的设备’”“按钮写‘连接设备’” | **应按要求显示** |
| **真实产品数据与必需状态** | 文件名、设备名、连接状态、表单标签、错误及恢复操作 | **按任务需要显示** |

默认拒绝把需求描述、系统提示词、功能列表、技术栈、布局规则、开发计划和回答说明写进 DOM、桌面客户端视图、移动页面或视觉稿。即使用户把这些文字写在提示词中，也先按指令处理；只有**明确要求将其作为页面文案**时才展示。

### 3.2 页面文案白名单

允许且鼓励保留：

- **导航与定位：** 页面名称、菜单名称、路径、必要分组标题。
- **操作：** 具体的按钮动词、控件标签、选项与快捷键。
- **业务信息：** 用户真实内容、字段、数量、单位、时间、数据说明。
- **状态与恢复：** 加载、完成、空状态、失败原因、重试或撤销。
- **必要说明：** 高风险确认、隐私/权限解释、复杂操作中的关键帮助、可访问文本。

对于清晰、自明的控件，不自动附加一行“此功能可以帮助您……”；信息可以由位置、标题、图标或交互本身表达时，删掉重复句子。文字过多时优先重组信息、分层披露或优化组件，而非将所有解释缩小字号塞入界面。

### 3.3 页面文案黑名单

默认**禁止在 UI 中出现**：

- 设计自述：`简洁现代的界面`、`采用 12×12 网格系统`、`精心打造的交互体验`、`设计原则`。
- AI 自述：`根据你的要求`、`我已为你实现`、`以下是功能展示`、`这里我们将`。
- 需求复述：`支持多设备组网、能力插件化、局域网优先、云端备份……` 直接变成首页大段说明（除非明确做产品介绍页）。
- 虚构承诺和数字：`效率提升 300%`、`超过 10 万用户`、`99.99% 可用`，没有真实依据一律不能展示。
- 开发/测试语：`TODO`、`Placeholder`、`Demo`、`Mock Data`、`API 尚未接入`、`功能待完善`、`组件展示区`；正式 UI 用真实状态或隐藏暂不可用功能。
- 装饰性废话：`开启无限可能`、`打造极致体验`、`一站式智能管理`、`让工作更加高效`、`欢迎来到未来`、不必要的第二行副标题。
- 多余的注释性标签：对每一个卡片或按钮重复解释用途、每个标题上方放一句眉题、为纯布局区块起“功能区域”之类的名字。

**源代码注释与页面文案分离：** 必要的程序注释可以保留在源码中，但注释、调试字符串、开发者元信息不能成为可见 UI。对框架自动生成的演示页、文档区、样板内容要主动清理。

### 3.4 文案长度与准确性

- 按产品术语命名：`设备`、`文件`、`连接`、`设置`，同一概念用词保持一致。导航和按钮优先短语，不为了凑文案写完整说明句。
- 按钮用明确动作，如 `复制到本机`、`删除`、`重试`；避免笼统的 `立即体验`、`了解更多`、`提交`（确实适用时可用）。
- 空状态通常一个标题 + 可选一条必要原因/帮助 + 一个操作就足够；不要插入鸡汤文案、Emoji 和超大装饰图。
- 错误提示要具体、可执行，如 `连接失败，请检查网络后重试`；关键错误和风险提示不因追求简洁而省略。
- 不编造用户记录、团队成员、评价、品牌合作、统计数据。原型需要演示数据时，仅在**开发/预览数据层**使用明确隔离的假数据，不将其冒充真实上线数据。
- 内容不足时保持真实空状态、骨架屏或最小功能结构。不要靠新增功能区、营销文案和额外卡片填满网格。

### 3.5 设计前的内容清单与设计后的逐字审查

生成前在内部形成“可见文案清单”（不放在页面）：`页面名称 → 导航 → 字段 → 操作 → 状态 → 必要帮助`。凡是不在清单中、且不是实际业务数据的文字，必须说明其必要性，否则删除。

交付前在**渲染界面**逐条核对文本节点、按钮、占位文本、伪元素 `content`、Tooltip、空状态与演示内容：

1. 是否有直接复制/改写自用户**任务指令**的内容？删除，除非用户明确要求显示。
2. 是否有“设计说明、宣传废话、为了填版面的文字”？删除。
3. 是否有虚构数据、未经证实的承诺和演示占位？改为真实数据/真实空状态。
4. 删除文字后是否影响完成任务、错误恢复或无障碍？受影响的必要文本恢复为最简正确版本。

> 示例：要求“做一个黑白极简的文件管理器，支持复制到本机，采用 12×12 网格”。页面可以有 `文件`、`设备`、`复制到本机`；页面不得出现 `黑白极简文件管理器`、`12×12 网格设计`、`本系统采用现代化布局` 作为自动生成的标题或说明。

## 4. 仅三套响应式网格

网格格式为“列 × 行”。**列是真实水平对齐系统；行是逻辑上的首屏组织参考。** 不为实现规则而锁死滚动页面的行高。

| 工作区可用宽度 | 网格 | 推荐外边距 | 栏间距 | 常见结构 |
| --- | --- | --- | --- | --- |
| **桌面 ≥1024px** | **12×12** | 32px | 20px | 导航 2–3 列，主内容 9–10 列 |
| **平板 600–1023px** | **9×9** | 24px | 16px | 主内容 6–9 列；辅助区可折叠 |
| **手机 <600px** | **4×12** | 16px | 12px | 主流程 4 列；少量 2+2 并排 |

- 判断依据是**页面/工作区实际可用宽度**，桌面应用窄窗口也可进入平板或手机布局。分屏、侧栏和嵌入容器优先考虑容器查询或平台等效机制。
- 标题、导航、列表、表格、卡片对齐列线，可跨列；不要求把每个控件填成一个单元格。
- 标题栏、侧栏、页脚、浮层不必强迫套进相同列跨度。组件内部可以使用 Flex/Stack 和必要的局部布局。
- `12/9/12` 行用于首屏或固定工作区的逻辑分组。长页面、聊天、表格、列表使用自然行高和滚动；禁止裁剪内容凑齐固定行数。
- 不为了填满网格新增空卡片、额外标题、描述或装饰；网格负责组织已有信息。

**Web 最小实现参考（项目已有布局体系时优先复用）：**

```css
:root {
  --grid-cols: 4;
  --grid-rows-guide: 12;
  --page-margin: 16px;
  --grid-gap: 12px;
}
@media (min-width: 600px) {
  :root { --grid-cols: 9; --grid-rows-guide: 9; --page-margin: 24px; --grid-gap: 16px; }
}
@media (min-width: 1024px) {
  :root { --grid-cols: 12; --grid-rows-guide: 12; --page-margin: 32px; --grid-gap: 20px; }
}
.page-grid {
  display: grid;
  grid-template-columns: repeat(var(--grid-cols), minmax(0, 1fr));
  column-gap: var(--grid-gap);
  row-gap: var(--space-4, 16px);
  padding-inline: var(--page-margin);
}
.page-grid > * { min-width: 0; }
/* --grid-rows-guide 只作规划，不应用于一般滚动容器的固定 grid-template-rows。 */
```

## 5. 排版、Token、边距与层次

### 5.1 简单且语义化的 Token

优先复用项目 Token。新项目最少定义：

```text
colors:  canvas / surface / surface-muted / text / text-secondary / border
         / primary / on-primary / focus / success / warning / danger
text:    title / section / body / meta / numeric
space:   4 / 8 / 12 / 16 / 24 / 32 / 48
radius:  none / small / medium / large
motion:  fast / normal / slow
layout:  columns / rows-guide / margin / gap
icons:   library / default-size / stroke-weight
```

- 间距遵循 4 或 8 的主要节奏，少数微调可例外。使用统一的圆角体系，不给每种卡片发明不同的半径。
- 只保留少量文本级别（标题、章节、正文、辅助），通过字体大小、字重、行距和留白区分，避免灰度过低的小字。
- 中文正文行高通常从 `1.5–1.7` 起步；长文本限制行宽；数值列和变化数字使用 `tabular-nums`，必要时对文件名做中间省略并可查看全名。
- 暗色主题需要重新核对色阶、对比度和字体观感，不机械要求字重全站降低一档。
- 嵌套圆角在间距均等时满足视觉共心，外半径可参考“内半径 + 间距”，按实际轮廓判断。
- 不因省边框牺牲控件边界和可见焦点。`:focus-visible` 的轮廓或双环阴影都可以使用，但必须清楚可辨。

### 5.2 信息层级与留白

- 识别单屏主任务、主操作、可选次要操作。信息量由实际功能决定，避免盲目居中、宽大空白或强行三列。
- 同类信息共享格式；主次区块通过空间、尺寸和必要分隔实现，少用卡片套卡片。
- 允许高密度后台、文件管理器、开发者工具保持紧凑；“高级感”不等于所有容器都大留白。
- 页面内容越少，越应减少组件数量；不得用文字解释空白。

## 6. 组件与交互语义

优先成熟组件，按真实任务选择：

| 目的 | 建议组件 | 关键检查 |
| --- | --- | --- |
| 选择字段值 | Select / Combobox / Radio | 值可见，选项多时可搜索 |
| 执行动作集合 | Dropdown Menu | 与字段选择区分，危险动作突出 |
| 即时开关 | Switch | 开/关明确且有可访问名称 |
| 多项勾选 | Checkbox | 标签与点击区域匹配 |
| 简短决策/确认 | Modal / Dialog | 焦点管理、Esc 与取消策略 |
| 长设置/复杂编辑 | Drawer / 页面 | 避免误关闭丢失输入 |
| 轻量反馈 | Toast | 不覆盖操作，重要错误可持久查看 |
| 危险操作 | 确认或可撤销机制 | 动作词准确、明确后果 |
| 信息补充 | Tooltip / 必要帮助 | 桌面键盘可达、移动端可访问 |

- 组件必须覆盖适用的 default、hover、focus、pressed、selected、disabled、loading、empty、error；不把交互全部藏在 hover 内。
- **IME：** 回车发送前检查 `isComposing` 和组合输入事件，避免拼音选字时误发送；不默认阻止 `compositionend` 之后固定 500ms 的所有回车。
- **滚动：** 流式或增量内容只在用户接近底部时跟随；用户主动向上浏览即暂停，提供回到底部的入口。避免每字模糊动画和高成本合成层。
- **拖拽：** 采用指针捕获/成熟库；有最小面板宽度、键盘替代操作和取消策略；不要未经要求在拖过 80% 时自动关闭面板。
- **动效：** 反馈与空间变化可使用约 `100–300ms` 的过渡；避免默认逐区块入场、无理由弹跳、光晕和复杂滚动动画。尊重减少动态效果设置。
- **文案仍受 §3 约束：** 状态、Toast、Tooltips、空状态也不能出现 AI 自述、提示词、废话或 Emoji。

## 7. 平台差异与可访问性

- **Web：** 语义 HTML；按钮执行动作、链接负责导航；字体缩放与响应式；关键内容不会被固定头尾遮挡；不同宽度没有水平溢出。
- **桌面客户端：** 优先高效工作区、键盘导航、快捷键、右键菜单、多窗格、可调整大小与持久化布局；不强行套手机卡片设计。
- **平板：** 适配横竖屏、触控、外接键盘与分屏；辅助导航可折叠。
- **手机：** 触控目标充足、安全区和输入法避让、主操作可达；避免复杂小浮层与多级嵌套卡片。
- **无障碍：** Web 参考 WCAG 2.2 AA：一般正文与背景对比度 ≥4.5:1，大字 ≥3:1；可见焦点、键盘操作、真实输入标签、图标按钮的可访问名称、错误恢复；状态不能仅靠颜色传达。
- 所有平台支持长文本、国际化、无数据、加载、失败、系统字体放大；有动效时支持减少动态效果。

## 8. 交付前的强制审查

**不要只检查源代码；优先检查实际运行页面、截图和最终可见内容。** 有条件时在桌面、平板、手机代表宽度分别验收。

### P0：立即修复，不得交付

- [ ] AI 自己添加的 Emoji 用于导航、按钮、功能、插画、空状态或提示（真实用户内容例外）。
- [ ] 页面渲染了用户提示词、需求复述、设计/技术说明、系统或开发者内部信息。
- [ ] 显示未经授权的真实感统计、虚构客户/评价/资质、无依据的营销承诺。
- [ ] 核心操作不能使用、关键内容缺失、重大无障碍障碍或隐私敏感信息泄露。

### P1：影响视觉与使用，应修复

- [ ] 未经指定就出现蓝紫渐变、霓虹色、彩色图标、无意义强强调色或任意颜色编码。
- [ ] 可见多余文字：装饰眉题、重复副标题、卡片功能讲解、AI 自述和占位文案。
- [ ] 使用多个风格不一的图标库、Emoji 字体后备图标、错位或不清晰图标。
- [ ] 违反桌面 `12×12` / 平板 `9×9` / 手机 `4×12` 基准，或为固定行数挤压内容。
- [ ] 关键状态缺失、弹窗不可访问、焦点不可见、移动端误触或布局溢出。

### P2：细节质量与一致性

- [ ] 不必要的多重边框、阴影、卡片嵌套、额外标签和视觉噪声。
- [ ] 字级过多、文本行长不当、数值跳动、文件名丢失扩展名。
- [ ] 动效过量、滚动抢控制权、暗色主题层次不清或对比度不足。

**审查动作：**

1. **看图标：** 逐一核对导航、按钮、状态、卡片、空状态；搜索本次新写的组件字符串中的 Emoji 与不一致的 icon 源。
2. **看颜色：** 检查 CSS/主题变量/内联样式中的颜色定义；非中性色逐个说明是既有品牌色、真正语义色还是用户明确要求，否则移除。
3. **看文本：** 收集最终可见文本（DOM/截图/原生视图），逐字过滤 §3 黑名单，确认无提示词泄露；重点检查 `placeholder`、`title`、Tooltip、伪元素和条件分支。
4. **看布局：** 检查三类宽度、可用窗口宽度、滚动内容、长文和空状态；取消为填满网格新增的装饰区域。
5. **看行为：** 实测核心操作、键盘、触控、加载/失败、暗色（若启用）、减少动画和可访问名称。

如没有实际运行权限或截图能力，执行静态审查并明确标注未验证项；禁止宣称视觉验收已通过。

## 9. 不同任务的输出纪律

- **生成 UI：** 先处理真实内容和主流程，遵守 §0–§8；不要在页面插入“设计说明”“开发备注”。完成后向用户简述实现位置、必要技术选择和实际验证结果。
- **重构 UI：** 保留已存在的业务文案、真实数据和核心交互；只清理有充分依据的冗余内容、异常颜色与错误图标。不要把整个产品的品牌身份无条件清零。
- **审查 UI：** 按 `位置/证据 → 严重级别 → 具体修复 → 如何验证` 输出最重要的问题；不给无证据的“高级感”评分，也不把审查说明写到页面。
- **用户明确要求鲜明品牌、多彩插画、营销文案或 Emoji 功能：** 在相应范围执行明确要求，其余区域继续保持一致性、克制和可访问性。
